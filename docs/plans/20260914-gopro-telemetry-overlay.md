# Наложение телеметрии RaceBox на видео GoPro

## Overview

Локальный инструмент, который берёт видео с одной или нескольких камер GoPro и телеметрию
с логгера RaceBox, сводит их по времени и выдаёт **готовый MP4** с наложенным оверлеем.
Аналог видеомодуля RaceChrono, но работающий на компьютере, а не на телефоне, и потому
существенно быстрее.

Решаемая проблема: сегодня наложить телеметрию на онбордовое видео можно либо в мобильном
приложении (медленно, ограниченная раскладка), либо вручную в видеоредакторе (долго и
неповторяемо). Инструмент делает это за один проход и с сохраняемым пресетом раскладки.

Критерии приёмки:

1. Из сессии 3429 (три чанка GoPro + RaceBox CSV) получается MP4 с четырьмя виджетами
2. Две-три камеры показываются одновременно (PiP), главную и врезку можно менять местами
   в произвольные моменты заезда
3. Картинка в превью браузера совпадает с отрендеренным файлом
4. Синхронизация телеметрии и видео точнее одного кадра при 60 fps

## Solution Overview

**Браузер рисует и показывает, ffmpeg склеивает.** Разделение выбрано из трёх вариантов
(полностью на Python со Skia, полностью в браузере на WebCodecs, и этот гибрид).

```
RaceBox CSV ──┐
              ├──→ sync ──→ session.json ──┐
GoPro MP4/LRV ┘        (общий таймлайн)     │
                                            ▼
                                   ┌─────────────────┐
                                   │  веб-редактор   │  превью, раскладка,
                                   │   (браузер)     │  точки переключения
                                   └────────┬────────┘
                                            │
                            layout.json + overlay.webm (RGBA)
                                            │
     исходные MP4 в полном разрешении ──────┴──→ ffmpeg ──→ out.mp4
```

Ключевые решения и их обоснование:

- **Превью через теги `<video>`, а не через свой декодер.** Самая дорогая часть редактора —
  декодирование и синхронный скраб нескольких потоков — достаётся от браузера бесплатно.
  Проигрывание идёт по `.LRV`-прокси GoPro, поэтому скраб остаётся отзывчивым на 4K-материале.
- **Оверлей рисуется ровно один раз, одним кодом.** Тот же canvas, что крутится в превью,
  отдаёт кадры в WebCodecs. Расхождение «в превью было так, а в рендере иначе» невозможно
  по построению.
- **Тяжёлое видео трогает только ffmpeg.** Браузер кодирует лишь оверлей — маленький RGBA
  без исходника. Поэтому кодек GoPro (здесь H.264, но бывает HEVC) не имеет значения.
- **Нормализованные координаты 0..1 во всей раскладке.** Превью рисуется на элементе
  произвольного размера, ffmpeg рендерит в полном разрешении; общими у них могут быть только
  доли, но не пиксели. Это главный механизм защиты от расхождения.
- **Телеметрия хранится словарём каналов, а не полями класса.** В `DDA_Reader` поля зашиты
  в `DDARecord.__slots__`, и поэтому там за всю историю не появилось ни одного источника
  данных кроме `.dda`. Здесь этой ошибки не повторяем — но и плагинную систему не строим.

## Technical Details

### Синхронизация (проверена на реальных данных)

Лесенка из трёх ступеней:

1. **UTC от GPS** — грубый якорь. И GoPro (`GPSU`), и RaceBox (колонка `Time`) отдают
   абсолютное UTC.
2. **Кросс-корреляция скорости** — точная привязка. Скорость GPS5 из GoPro против колонки
   `Speed` из RaceBox.
3. **Ручной слайдер** — для источников без UTC и для случаев, когда автоматика промахнулась.

Измерено на сессии 3429 (27 минут перекрытия):

| Величина | Значение |
| :--- | :--- |
| Корреляция при нулевом лаге | +0.9606 |
| Пик корреляции | +0.9997 |
| Лаг в пике | +1.40 с |
| Разброс лага по 8 окнам | +1.30…+1.40 (это шаг сетки, не дрейф) |

Выводы, зашитые в реализацию:

- UTC на одной шкале у обоих устройств: проблем с leap seconds и часовыми поясами нет
- **Кросс-корреляция обязательна**, а не опциональна: 1.4 с это 84 кадра при 60 fps
- **Компенсацию дрейфа часов не делать** — за 27 минут дрейфа нет
- **Пик доводить субсэмплово**, параболой по трём точкам вокруг максимума: на сетке 10 Гц
  разрешение 0.1 с, то есть 6 кадров, чего недостаточно

### Формат `session.json`

Контракт между Python и браузером. Python не знает про отрисовку, браузер не знает про парсинг.

```json
{
  "session": { "start_utc": "2026-09-12T12:29:35.340Z", "track": "Slovakia Ring" },
  "channels": {
    "speed":  { "role": "speed",      "unit": "km/h", "rate": 25, "samples": [] },
    "lean":   { "role": "lean",       "unit": "deg",  "rate": 25, "samples": [] },
    "accel":  { "role": "accel_long", "unit": "g",    "rate": 25, "samples": [] },
    "lat":    { "role": "lat",        "unit": "deg",  "rate": 25, "samples": [] },
    "lon":    { "role": "lon",        "unit": "deg",  "rate": 25, "samples": [] }
  },
  "laps":  [ { "n": 1, "t_start": 120.4, "t_end": 281.1, "best": false } ],
  "gates": [ { "id": "sf", "lat": 48.0555, "lon": 17.5665, "bearing": 272.4 } ],
  "envelope": [[48.0555, 17.5665], []],
  "clips": [
    { "id": "cam_front", "files": ["GH013429.MP4", "GH023429.MP4"],
      "offset_s": 0.0, "duration_s": 1733.7, "proxy": "GL013429.LRV" }
  ]
}
```

Время внутри `session.json` — секунды от `session.start_utc`, не абсолютные метки.

### Формат `layout.json`

```json
{
  "output": { "width": 1920, "height": 1080, "fps": 60 },
  "slots":  [ { "id": "main", "rect": [0, 0, 1, 1] },
              { "id": "pip",  "rect": [0.72, 0.04, 0.26, 0.26] } ],
  "cuts":   [ { "t": 0.0,   "main": "cam_front", "pip": "cam_rear"  },
              { "t": 184.2, "main": "cam_rear",  "pip": "cam_front" } ],
  "widgets":[ { "type": "speed", "pos": [0.04, 0.86], "scale": 1.0 } ]
}
```

`cuts` — разреженный список: пишутся только моменты **смены** состояния, между ними
расстановка держится. Такая форма ложится один в один на `enable='between(t,a,b)'` в ffmpeg.

### Граф фильтров ffmpeg

База — чёрный кадр нужного размера. Каждая тройка «камера + окно времени + слот» становится
однотипным overlay-фильтром, поэтому генератор графа — обычный цикл по `cuts`:

```
[black] ← cam_front (0–184с,  слот main, scale 1920x1080)
        ← cam_rear  (0–184с,  слот pip,  scale 500x281)
        ← cam_rear  (184с–…,  слот main)
        ← cam_front (184с–…,  слот pip)
        ← overlay.webm (весь ролик)
        → h264_videotoolbox
```

Чанки GoPro склеиваются заранее демультиплексором `concat`, смещения синхронизации задаются
через `-itsoffset` на входе, звук берётся с одной выбранной камеры целиком.

### Расчёт производных каналов

- **Скорость** — из GPS напрямую, единственный честно измеренный канал
- **Разгон/торможение** — из `GForceX` RaceBox либо центральной разностью скорости. Выбрать,
  сравнив оба варианта на данных сессии 3429
- **Угол наклона** — считать из траектории: `lean = atan(v · (dψ/dt) / g)`. С акселерометра
  брать нельзя: в установившемся повороте мотоцикл наклоняется ровно настолько, чтобы
  равнодействующая совпала с его вертикальной осью, поэтому закреплённый на нём датчик
  покажет боковое ускорение около нуля. Расчёт из траектории не зависит ещё и от способа
  крепления логгера. Сверить с колонкой `LeanAngle` от RaceBox.
- **Огибающая кругов** — усреднять по времени или по индексу **нельзя**: круги разной
  длительности, и сэмпл номер 500 на быстром и медленном круге это разные места трассы.
  Правильно: параметризовать эталонный круг по пройденному пути `s`, спроецировать точки
  остальных кругов на эталон (координаты Френе), получив пару «позиция вдоль трассы» и
  «боковое смещение». Этот же механизм нужен для сравнения кругов.
